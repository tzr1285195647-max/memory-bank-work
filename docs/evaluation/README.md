# 可信机制评测（审计拦截率基准）

这是"给可信一个数字"的评测：对已确认故事构造对抗编辑，度量证据审计闸门的
**篡改拦截率**（应拦的拦住了吗）与**润色误拦率**（不该拦的误伤了吗）。
评测集、脚本、报告全部随仓库提交，任何人可复现。

## 方法

- 评测故事：《晒谷的秋天》——6 句口述原文（已确认碎片）、9 条证据 claim，
  全部定义在 [`backend/audit_eval.py`](../../backend/audit_eval.py) 中，无外部依赖。
- 评测集：**50 条编辑**
  - 25 条**事实篡改**（应拦截）：篡改年份/年龄、编造人物、编造地点、编造事件经过、编造感受评价，共 6 类；
  - 25 条**正常润色**（应放行）：同义微调、语序调整、拆分合并、过渡语气、摘要复述，共 5 类。
- 判定：审计返回任何 `unsupported` 发现即视为"拦截"。

## 运行

```bash
# 本地确定性规则层（无需服务与密钥）
python backend/audit_eval.py local

# 真实模型层（双层门实测）：需要 .env 配置 AGENT_MODE=llm 与模型密钥
python backend/audit_eval.py prepare-db   # 先停止后端，向演示库插入评测故事
python backend/run.py                     # 另开终端启动后端
python backend/audit_eval.py llm          # 逐条走 /stories/{id}/review 双层复审
```

## 当前结果

### 本地确定性规则层（`audit-benchmark-local.md`）

| 指标 | 修复前（2026-10-07 基线） | 修复后（当前规则） |
| --- | --- | --- |
| 篡改拦截率 | 88%（22/25） | **100%（25/25）** |
| 润色误拦率 | 4%（1/25） | **0%（0/25）** |
| 判定一致率 | 92%（46/50） | 100%（50/50） |

修复内容（15 项回归测试见 `backend/tests/test_evidence_audit_hardening.py`）：

1. **汉字数字年龄锚点**：anchor 同时识别阿拉伯数字与汉字数字（十二岁 -> 12 岁）并比较数值；
2. **常见实体词残差核对**：高重合度分句的未匹配残差若含证据中没有的人物称谓/地点词，判为新增实体；
3. **短过渡语豁免**：句首那时候/当时/后来/记得/如今（含单独成句）先剥离再核对。

### 曾发现的 3 条漏报（均已修复，保留机理记录）

| 编号 | 手法 | 当时的漏报原因 | 修复方式 |
| --- | --- | --- | --- |
| T04 | 十二岁改为十四岁 | anchor 只识别阿拉伯数字；共享前缀凑满重合下限 | 汉字数字年龄锚点 |
| T09 | 长句内插入「三姑」 | 插入后重合度依然很高 | 人物称谓残差核对 |
| T12 | 晒谷场改为学校操场 | 同上 | 地点词残差核对 |

误拦样本 B16（短过渡语「那时候」单独成句低于重合下限）以过渡语豁免修复。

这正是产品采用**双层门**的原因：规则层零成本拦下绝大多数编造；规则层修复后，
模型审计层继续负责规则难以覆盖的语义级篡改，最后仍需家人人工确认才能发布。
真实模型层的实测（deepseek-flash 与 deepseek-chat 对照，基于修复前规则层）见
[audit-benchmark-llm.md](audit-benchmark-llm.md)。

## 诚实声明

评测集由项目团队构造，存在"自己出题自己考"的天然局限：篡改手法覆盖了演示中
实际出现过的幻觉类型（编造年份、人物、事件），但不足以等价于真实用户场景的分布。
评测集会随产品迭代持续扩充；如果你发现规则层的绕过手法，欢迎提 issue 补充用例。
