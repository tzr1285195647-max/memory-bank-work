# 记忆银行 · 现场演示脚本

适用场景：**现场路演 + 演示视频**（你确认的形式）。全程在开发者工具模拟器里操作，不依赖公网、不需要真机、不需要备案域名。

> P0 默认使用 `.env` 中的 `AGENT_MODE=mock`。它不是静态假页面，而是由本机 LangGraph、确定性 Agent、SQLite 与真实录音接口完整执行；区别只是智能判断采用可复现的本地规则，不调用外部模型。

- 主演示：**4 分钟**（下方 8 步，可压缩到 2 分半）
- 深度演示：**8 分钟**（含撤回授权、授权版本校验、后端数据落库）
- 演示视频：按本脚本录一遍即可

---

## 0. 开演前 5 分钟准备（照做即可）

```powershell
# 1) 启动后端（保持这个窗口开着，别关）
cd D:\记忆银行
python backend/run.py

# 3) 只读自检：确认演示依赖可用且不改动数据（开演前用这个）
python backend/demo_check.py --readonly

# 4) 只有当你要验证"上传/生成/确认"整条链路时，才跑完整自检（会写数据）
python backend/demo_check.py
python backend/reset_demo.py     # 完整自检跑完，重置回干净数据

# 5) 启动/打开微信开发者工具，确认：
#    - 模拟器打开（Ctrl+Shift+A）
#    - 「详情 → 本地设置」勾选「不校验合法域名」
#    - 控制台出现 [font] 思源宋体加载结果: [true, true]
```

进入小程序后还可以在「我的」页面点击**一键演示自检**，确认本机后端、主题数据和确定性 Agent 均已就绪。

**演示前必须重置数据**：`python backend/reset_demo.py`（需先停后端）。

> 注意：**完整自检会往库里写测试故事与录音**，所以顺序是「完整自检 → 重置 → 开演」，或者干脆只用 `--readonly`。

## 1. 演示主线：可信闭环

一句话定调（开场就说，评委才知道该看什么）：

> 我们要证明的不是"AI 会写故事"，而是**AI 写的每个字都能追回老人的原声，且发布权始终在人手里**。

主线八步，对应产品规则的八条硬约束：

| 步骤 | 动作 | 要证明的产品规则 |
|---|---|---|
| 1 | 登录进入 | 身份分流（长辈 / 家人） |
| 2 | 首页与主题 | 一次只讲一件小事 |
| 3 | 按下讲述、录音 | 老人意愿优先、操作极简 |
| 4 | 结束录音 → 生成 | 原声上传留存 |
| 5 | 预览页看来源标识 | **证据可追溯** |
| 6 | 改一段文字 → 重审 | **AI 内容必须人工确认** |
| 7 | 确认 → 故事书 | 人工确认后才发布 |
| 8 | 家庭看板 + 撤回授权 | 家人协作边界、**撤回即删除** |

## 2. 逐步脚本（含解说词）

> 括号里是**你要做的操作**，引号里是**建议说的话**。每步都标了「评委该看到什么」，方便你在现场引导视线。

### 第 1 步 · 身份与登录（20 秒）

**操作**：模拟器里如果已登录，先「我的 → 退出登录」，回到 01 欢迎页。

- 01 欢迎页 → 点「我是长辈，开始讲述」
- 02 身份选择 → 点「长辈」
- 03 登录页 → 点底部**「演示账号」提示块**（自动填入 `13800008899 / 123456`）→ 点「登录」

**解说**：「入口只问一件事——你是讲述的人，还是陪伴的人。这两个身份后面看到的内容和能做的操作完全不同。」

**评委该看到**：设计稿还原的欢迎页与身份选择页，宋体正文，四栏底部导航。

### 第 2 步 · 首页与主题（25 秒）

**操作**：进入 04 长辈首页 → 指出「今日叙事」卡 → 点「按下讲述」进入 05 主题选择。

**解说**：「首页只放一件事：今天想讲点什么。下面这句是刻意的——『一次只讲一个小故事，不用从出生讲起』。老人被问『讲讲你的一生』是会卡住的，所以我们把入口拆成乡、校、业、家四个容易回忆的具体切口。」

**评委该看到**：四个主题项（乡/校/业/家），每个都有具体提示语。

### 第 3 步 · 多轮采访与录音（50 秒）

**操作**：05 选「我的家乡」→ 进入 06 录音页 → 回答屏幕上的第一问 → 暂停后看到自动填入且明确标注的“演示转写” → 按原声校对 → 选择「原味口述 / 自然整理 / 适合成书」之一 → 点「保存本轮，听下一问」→ 再回答一轮 → 点「讲完了，生成故事」。

**解说**：「Agent 每次只问一个问题，并根据七要素缺失情况决定下一问，最多三轮，也可以随时结束。每轮回答都有独立原声和证据编号，不会把几段来源混在一起。」

**评委该看到**：可编辑的演示转写、三种整理方式、轮次从 1/3 变成 2/3、问题发生变化、已保存轮次出现勾选状态。

> **现场话术备选**：如果不想现场说话（环境嘈杂），可以只录 3~5 秒然后直接结束——后面的流程完全一样。

### 第 4 步 · 结束并生成（20 秒）

**操作**：点「讲完了，生成故事」，观察「整理口述文字 → 提取记忆要点 → 核对原声依据」三阶段进度。

**解说**：「原声这一刻就上传到服务端了，服务端用内容的哈希做对象键，不信任我们传的文件名。」

**评委该看到**：按钮 loading 态 → 自动跳转 07 故事预览页。

### 第 5 步 · 证据可追溯（40 秒）——**本演示的核心**

**操作**：停在 07 故事预览页，**先不要点任何按钮**。

**解说**（指着来源标识）：「请注意这一行——『原声 00:0X · 自然整理』。它把两件事绑在一起：这段文字对应的原声有多长、以及它是怎么被整理出来的。」

**操作**：在「分轮原声」中分别点击第 1、2 轮，再查看证据条目上的来源轮次。

**解说**：「这是刚录的那段原声，现在是从服务端读回来的，不是本地缓存。也就是说，任何一段 AI 整理的正文，都能回到它依据的那段声音。这是我们对『AI 会不会编』这个问题的回答——不靠承诺，靠可追回的来源。」

**再指着 `AI 整理 · 待确认` 标签**：「所有 AI 生成或整理的内容都必须带这个标识，这是硬规则。」

**评委该看到**：每轮原声可单独回听，证据条目注明来自哪一轮；卡片上有「AI 整理 · 待确认」标签。

### 第 6 步 · 人工确认边界（40 秒）

**操作**：点「修改文字」→ 在正文里**加一句原文里没有的事实**（例如「那年我十二岁。」）→ 点「保存修改」。

**解说**：「我故意加了一句老人没说过的话。保存后系统立即重新核对证据，并指出这句话没有原声依据，确认按钮也被禁用。规则是：**只要人改过，就必须重新审计，不存在改完直接发布这条路**。」

**操作**：删除刚才新增的事实并再次保存，看到“审计通过”；也可以点「继续补充讲述」，回到同一个采访会话补录缺失信息。

**解说**：「只有人点了确认，它才会进故事书。AI 不能自己发布任何东西。」

**评委该看到**：无证据修改被明确标出且无法确认；修正或补录后才能确认并进入故事书。页面底部还可以放弃本次草稿，系统只删除本次临时原声。

### 第 7 步 · 时间轴与家庭纪念册（40 秒）

**操作**：09 故事书 → 展示时间轴 → 按人生阶段筛选或搜索关键词 → 点「把故事排成一本书」→ 依次展示封面、目录和阅读视图。

**解说**：「每条都带着年份、人生阶段、原声时长和整理方式。积累下来的故事不是停在数据库里，而是可以自动排成家庭纪念册，并复制成完整文本继续排版。」

### 第 8 步 · 家人协作与撤回（60 秒）——**留到最后，因为会清空数据**

**操作**：以家人身份登录 → 打开「家庭看板」的待确认故事 → 选择“补充回忆”或“修改建议”并提交。退出后以长辈身份登录 → 再打开同一故事 → 逐条“采纳建议”或“暂不采用” → 完成最终确认。

**解说**：「家人的补充会单独保存，不能直接混进老人的原话，也不能替老人发布。只要还有建议没处理，确认按钮就会保持禁用；最终决定权一直在长辈。」

**操作**：返回「我的」→ 点「**撤回授权并删除内容**」→ 确认。

**解说**：「这是最难做、但必须做的一条。老人随时可以撤回授权——撤回后，他的录音、转写、故事**从服务端被删掉**，我们去后端确认一下。」

**操作**（深度演示才做）：切到后端窗口，或用浏览器打开 <http://127.0.0.1:8787/docs> 说明数据已被清空；也可以跑 `python backend/smoke.py` 看故事数变成 0。

**解说**：「注意，删的是内容，**审计记录保留**——这是合规要求：内容可以被遗忘，但『谁在什么时候授权、谁撤回』这件事不能被抹掉。」

## 3. 深度演示加演项（评委追问时用）

| 追问 | 当场怎么证明 |
|---|---|
| 「AI 会不会偷偷编造？」 | 07 屏的 AI 标识 + 来源标识 + 「改过就退回待确认」。设计稿里七要素缺失时留空、不猜测，对应 `missingFields`（P1-2 落地） |
| 「旧版本的写入怎么办？」 | 后端对每个写请求校验 `consentVersion`。可以用 `/docs` 页面手改一个错误的 `consentVersion` 发请求，会返回 403 |
| 「数据是假的吗？」 | 打开 <http://127.0.0.1:8787/docs> 直接调接口给评委看；或 `python backend/smoke.py` 打印服务端真实数据 |
| 「老人不会用怎么办？」 | 06 屏只有一个按钮、字号 34px；底部导航只有四栏。设计稿里长辈端顶栏用浅绿区分 |
| 「多端/上云怎么办？」 | 后端是标准 FastAPI，接口契约不变，只换部署位置；小程序端只改 `config.js` 的 `baseUrl` |
| 「原声存哪、安不安全？」 | 对象键用内容哈希、不信任原始文件名；生产环境把 `/media` 换成带签名的短期 URL（已在 `docs/BACKEND.md` 标注） |
| 「双人讲述怎么区分？」 | 06 屏选择“双人访谈”，每轮由用户确认讲述者是长辈还是家人；不在没有声纹模型时伪装成自动分轨 |
| 「最后能形成什么？」 | 故事书点“把故事排成一本书”，现场展示可改书名的封面、年代目录、连续阅读和文本导出 |

## 4. 故障预案（现场必看）

| 故障 | 现象 | 现场处理 |
|---|---|---|
| **后端没起来** | 登录弹「后端未连接」 | 小程序会提示并允许「本地进入」——**继续演示**，并在解说时说明「当前是本地演示模式」；同时后台窗口补启动后端 |
| **后端中途挂了** | 保存/确认报错 | 重跑 `python backend/run.py`；小程序会自动降级到本地数据，10 屏与录音仍可演示 |
| **域名校验没关** | 请求全部失败 | 「详情 → 本地设置」勾选「不校验合法域名」，重新编译 |
| **字体没加载** | 中文是默认字体 | 影响观感不影响功能，继续演示；控制台看 `[font]` 日志定位 |
| **麦克风权限被拒** | 点录音无反应 | 会弹引导去设置；模拟器里可在「设置 → 权限」重置 |
| **录音太吵/太短** | 原声几乎听不到 | 提前录一段 10 秒的备用录音，把文件放进 `backend/.data/objects/` 并预置到演示库里（或用「原味口述」示例故事代替） |
| **模拟器卡死/白屏** | 界面空白 | 关掉项目重新打开（不要反复点编译）；必要时重启开发者工具 |
| **投屏分辨率低** | 评委看不清小字 | 模拟器缩放到 100% 以上；优先展示 30px 以上的大标题 |

**保险做法**：提前录一遍**演示视频**，现场若出故障直接放视频。这也是你确认的方案之一。

## 5. 演示视频录制清单

| 项 | 要求 |
|---|---|
| 时长 | 3~5 分钟（比现场更从容，可以慢慢说） |
| 分辨率 | 1920×1080，模拟器缩放到 100% 以上，字体清晰 |
| 声音 | **必须有解说**——评委需要听到"为什么这么设计"，而不只是看操作 |
| 必录片段 | 第 5 步回听原声（把音量放出来）、第 6 步改完打回待确认、第 8 步撤回后数据消失 |
| 开头 | 一句话说清问题：老人愿意讲，但录音散落、转写可能被改写、没人知道哪句是原话 |
| 结尾 | 回到那一句：**每个字都能追回原声，发布权始终在人手里** |
| 备份 | 视频文件同时放 U 盘与云端（现场网络不可靠） |

## 7. 演示纪律（三条）

1. **不说"AI 写得很好"**，只说"这段话能追回到哪段原声"。
2. **不跳过"待确认"** 这一步——那是产品主张，不是流程负担。
3. **被问到外部能力**，明确说明当前边界：真实 ASR、短信、跨设备邀请和微信发布需要上线资质；本机演示不伪装成这些外部服务。
