# 记忆银行小程序 · 技术方案

- 版本：1.0（待确认）
- 日期：2026-09-11
- 依据：`docs/DESIGN_SPEC.md`（10 屏设计规格）、`docs/PRODUCT_FOUNDATION.md`（产品与安全基线）
- 技术选型：**微信原生小程序** + 在线思源宋体（子集）

---

## 1. 一句话方案

一个**单包小程序**（不分子包），长辈与家人在 02 屏分流身份、共用同一套页面骨架与后端接口；前端先用 Mock 数据跑通 10 屏与导航闭环，再逐屏接入真实 API。

---

## 2. 技术选型与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 前端框架 | 微信原生（WXML/WXSS/JS） | 设计稿 207 个元素全部是圆角矩形 + 文本，原生能 1:1 还原；调试链路最短，包体最小 |
| 语言 | JavaScript + JSDoc 类型注释 | 不引入 TS 构建链，保持零构建；对长辈端这种低频页面足够 |
| 状态管理 | 轻量全局 store（`app.globalData` + 事件订阅） | 10 屏规模不需要 MobX/Redux；跨页只需共享「身份、家庭 ID、当前故事草稿」 |
| 数据请求 | `wx.request` 封装 `utils/request.js` | 统一注入 token、consent 版本、错误映射 |
| 录音 | `wx.getRecorderManager()` | 官方能力，支持 mp3/aac，可拿到时长 |
| 播放 | `wx.createInnerAudioContext()` | 支持 `seek` 与 `currentTime`，07 屏要显示「原声 03:42」 |
| 字体 | `wx.loadFontFace` 加载**思源宋体子集** | 设计稿中文实际不是 Lora（Lora 无中文字形），思源宋体观感最接近 |
| 后端 | 沿用原计划的 FastAPI（独立仓库/目录） | 与小程序通过 HTTPS + 域名白名单通信 |

**不选 Taro/uni-app 的原因**：当前只需要微信一端，多端能力用不上；原生省掉一层构建，出问题时排查路径更短。将来若要出 H5 或支付宝版，页面结构可以按本文档的组件划分平移。

## 5. 状态管理

```js
// store/index.js 结构
{
  role: null,              // 'elder' | 'family'
  token: null,             // 访问令牌（短期）
  user: null,              // { id, displayName, phoneMasked }
  familyId: null,
  currentTopic: null,      // 05 选中的主题
  currentDraft: null,      // 07 待确认草稿 { id, title, text, audioDuration, evidence }
  recording: { active: false, seconds: 0, tempFilePath: null },
}
```

持久化：`role`、`token`、`familyId`、`user` 写 `wx.setStorageSync`，启动时恢复；`currentDraft` 只留内存，避免未确认内容被误恢复。

## 8. 录音与播放

### 8.1 录音

```js
const recorder = wx.getRecorderManager();
recorder.start({
  duration: 600000,        // 上限 10 分钟，防误触长时间录音
  format: 'mp3',           // 兼容性最好
  sampleRate: 16000,       // 语音够用，体积小
  numberOfChannels: 1,
  encodeBitRate: 48000,
});
recorder.onStop((res) => { /* res.tempFilePath, res.duration */ });
```

要点：

- 首次进入需 `wx.authorize({ scope: 'scope.record' })`，被拒后引导去 `wx.openSetting`。
- 页面 `onHide` 必须 `recorder.stop()`，避免后台占用麦克风。
- 计时用 `Date.now()` 差值而非累加，防止定时器漂移；06 屏显示 `mm:ss`。
- 「独自讲述 / 双人访谈」目前是**模式选择**，设计稿没有双人分轨的界面；建议先做选中态样式，双人分轨留到 P1。

### 8.2 上传

`wx.uploadFile` 直传后端，字段：`familyId`、`topicId`、`consentVersion`、`durationMs`、`file`。后端返回 `assetId` 后进入转写流程（ASR）。

### 8.3 播放

用 `innerAudioContext`，`src` 从后端换取**短期签名 URL**（不暴露长期地址），并监听 `onTimeUpdate` 更新进度与 `03:42` 显示。切页时 `destroy()` 释放。

## 9. 后端接口契约

### 9.1 通用约定

- 传输：HTTPS + JSON；鉴权 `Authorization: Bearer <token>`。
- **每次写请求都必须携带 `consentVersion`**；后端在开始与提交前各校验一次，旧版本一律丢弃（安全基线要求）。
- 所有业务查询按 `familyId` 范围，禁止只凭资源 ID 查询。
- 错误格式：`{ code, message, detail? }`，401/403 由 `utils/request.js` 统一跳登录。

### 9.2 接口清单

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| POST | `/auth/login` | 手机号+密码登录 | 返回短期 access token |
| POST | `/auth/sms` | 发送验证码 | 03 屏「验证码登录」 |
| GET | `/me` | 个人资料与统计 | 10 屏 |
| GET | `/home` | 今日叙事 + 最近故事 | 04 屏 |
| GET | `/topics` | 主题列表 | 05 屏 |
| POST | `/recordings` | 提交录音（multipart） | 06 屏 |
| GET | `/stories` | 故事列表（分页、排序） | 09 屏 |
| GET | `/stories/:id` | 故事详情（含证据与来源） | 07 屏 |
| PATCH | `/stories/:id` | 修改正文 | 07 屏编辑 |
| POST | `/stories/:id/confirm` | 确认故事 | 老人/创建者确认 |
| POST | `/stories/:id/reject` | 退回补充 | 家人视角 |
| GET | `/family` | 成员与进度 | 08 屏 |
| POST | `/family/invite` | 邀请家人 | 08 屏「已邀请 3 人」 |
| POST | `/consent/revoke` | 撤回授权并删除内容 | **设计稿缺，规则要求** |

### 9.3 核心数据模型（与产品规则对齐）

```text
Family        家庭（权限边界）
User          用户（老人/家人）
Membership    user × family × role
Topic         主题（乡/校/业/家）
Recording     录音（assetId, durationMs, consentVersion）
Transcript    转写分段（时间码，为证据链服务）
Claim         提取事实（七要素字段 + 原文片段）
Story         故事（标题、正文、状态）
StoryEvidence claim × 录音时间码
ConsentGrant  授权（scope、version、撤销时间）
AuditEvent    审计事件（不可静默覆盖）
```

**七要素**：`time / place / people / event / result / impact / feeling`，缺失即 `null` 并进 `missingFields`，不得推测。07 屏目前只展示自然段，**建议加一个「要素完整度」轻量视图**（见第 12 节）。

## 10. 隐私与合规

- **域名白名单**：`request` / `uploadFile` / `downloadFile` 的域名需在微信公众平台配置；开发阶段用开发者工具「不校验合法域名」开关。
- **字体域名**：若走 `wx.loadFontFace` 加载 CDN 字体，同样涉及域名与 HTTPS 要求，**需在平台配置**（细节见下节，待验证项）。
- **录音授权**：`scope.record` 必须在使用前申请，被拒要有引导文案。
- **日志**：不得记录转写正文、录音地址、姓名、手机号明文（手机号统一 `138****8899` 形式展示）。
- **撤回**：提供 `POST /consent/revoke`，撤回后删除内容但保留审计事件（设计要求，且需在 UI 上给出入口）。
- **用户隐私协议**：小程序需配置隐私协议并在首次录音前弹窗告知。

## 11. 字体方案（含待验证项）

**事实**：设计稿全部文本标为 `Lora`，但 Lora 只有拉丁字形，**中文部分是 Figma 用 fallback 字体渲染的**（我重建预览时也复现了这一点）。因此中文必须换成有中文字形的宋体。

**方案**：思源宋体（Noto Serif SC，SIL OFL 可商用）子集化：

1. 用 `fonttools` 按页面实际用字生成子集。全稿文本量很小（160 个文本节点，去重后约 300–500 个汉字），加上后续页面文案，按 1500 字预估：
   - WOFF2 约 0.8–1.2 MB；TTF 约 1.5–2 MB。
2. 小程序加载方式二选一：
   - **CDN + `wx.loadFontFace`**：需 HTTPS、需配置域名、需设 `global: true` 使其跨页生效；存在首次加载白屏风险，需配合降级。
   - **本地 `assets/fonts/` + `@font-face`**：无域名依赖，但字体体积计入**主包 2MB 上限**——1500 字子集很可能撑爆，**不建议**。
3. **务必做降级**：`font-family: 'SourceHanSerifSC', 'Songti SC', 'STSong', serif`。哪怕字体加载失败，iOS 落宋体、Android 落系统衬线，版式不崩。

> **待验证（我不能确认，需你或我在能联网的环境实测）**：
> - `wx.loadFontFace` 当前版本是否要求字体域名加入 downloadFile 白名单（我记得需要，但未能访问官方文档核实——官方页面在我的网络环境下解析失败）。
> - Android 端 `loadFontFace` 对 woff2 的支持是否完整（历史上有过只吃 ttf 的情况）。
> 建议：先按 CDN + TTF 子集实现并实测两端；若 Android 异常，退回「标题切图 + 正文系统宋体」。

## 15. 多智能体层（后端核心）

后端真正的核心是**五类智能体围绕证据链协同**，不是 CRUD。详见 [`AGENTS_ARCHITECTURE.md`](AGENTS_ARCHITECTURE.md)。

| 智能体 | 关键约束 |
|---|---|
| 采访导演 | 老人说停即停；同一缺失项不重复追问 |
| 证据抽取 | 每条事实必须带原文片段与来源轮次，找不到就留空 |
| 写作 | 只用已抽取证据，不得新增事实 |
| 写作审计 | 逐句核对引用与原文，无证据句子一律报出 |
| 冲突处理 | 矛盾讲述并列保留，不裁定 |

协同机制：`Send` 并行抽取每轮讲述、顶层 `interrupt` 实现采访与人工确认两处暂停、
SQLite checkpoint 支持跨进程恢复、授权闸门不符即改道删除。

小程序已接入该流程：每轮执行「独立录音 → 人工校对 → 提交证据 → 获取下一问」，
讲述者可随时结束，最多三轮；之后进入写作与审计。预览页会展示**分轮原声**、
**证据链（每条事实 + 原文 + 来源轮次）**与**缺失要素**。
# P1 记忆时间轴（已完成）

- 故事书支持时间轴与列表双视图，按年份正序/倒序浏览。
- 支持童年、求学、工作、家庭、晚年与未分类筛选。
- 长辈可在确认前补充发生年份和人生阶段；家人只读。
- 本地真机演示与后端使用同一套字段和分组规则。
- 旧 SQLite 数据库启动时自动补列，不需要清空已有故事。
