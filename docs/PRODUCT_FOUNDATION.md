# 记忆银行产品化基础决策

## 当前目标

先交付一个可单机部署、可内部试用、后续可替换模型和云服务的 Beta。保持模块化单体，不在验证真实用户需求前拆微服务。

## 已确定的边界

- API 与工作流：FastAPI + LangGraph。
- 生产业务数据：PostgreSQL；测试允许 SQLite。
- 后台协调：首版使用 PostgreSQL 事务队列（租约、重试、幂等均落库）；吞吐量确有需要时再增加 Redis 唤醒层，避免首发多维护一个事实来源。
- 大文件：ObjectStorage 接口，本地实现用于开发，S3 兼容实现留作部署适配。
- 认证：短期访问令牌；家庭成员关系是权限边界。
- 审计：授权、写入、审批、发布、撤回与删除均形成不可静默覆盖的事件。
- AI Provider：LLM、ASR、TTS 分别定义接口，Mock Provider 始终可运行。

## 安全基线

- 所有业务查询必须带 `family_id` 范围，禁止仅凭资源 ID 查询。
- 写工具在开始和提交前都校验 `consent_version`；旧版本的异步结果一律丢弃。
- 上传文件使用服务端生成的对象键，不信任原始文件名。
- 文件同时校验声明 MIME、扩展名和文件头，并设置体积上限。
- 密码只保存 Argon2 哈希；生产环境不允许默认 JWT 密钥。
- Trace 默认不写入原始音频和完整敏感文本。

## 外部输入稍后需要

- 首发部署地区及云厂商。
- 模型、ASR、TTS 供应商与密钥。
- 登录方式：邮箱、手机号、微信或企业身份系统。
- 内测用户角色和“本人/家属谁能批准”的业务规则。
- 样例音频及其明确测试授权。
- 数据保留期限、备份删除期限和隐私文本。
