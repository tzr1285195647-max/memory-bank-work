# 已知边界与演进路线

> 记忆银行当前阶段定位是**本机 / 局域网演示**：一台电脑跑后端，微信开发者工具或同网段真机访问。
> 这是有意的选择——先把"可信证据链"这条核心链路做扎实，再谈规模化。
> 本文如实列出当前边界、为什么现在这样，以及每条边界的演进方向。**原则不变：设计不冒充实现，下表"规划中"的能力不进入演示与提交材料。**

## 核心资产在服务端，端是可替换的

五 Agent 管线、证据链、事实审计、LangGraph 采访全部实现于 FastAPI 后端，通过 REST API 对外服务。
前端（现为微信原生小程序，14 个页面）只是壳。这意味着下述任何演进都**不需要重写核心逻辑**。

## 边界与演进

| # | 当前边界 | 为什么现在这样 | 演进方向 |
| --- | --- | --- | --- |
| 1 | 单机 SQLite 业务库 + 单进程任务队列 | 演示期零部署依赖，评委克隆即可跑；SQLite 免运维 | 迁移 Postgres（SQL 语义兼容）；任务队列拆分为独立 Worker 进程，支持横向扩容 |
| 2 | 本机部署（127.0.0.1 / 局域网 HTTP） | 微信开发者工具本地调试无需域名与备案 | 公网路径：HTTPS + ICP 备案域名 → 配置微信合法域名 → 云托管或自托管（Docker）；`JWT_SECRET` 换随机值并纳入密钥管理 |
| 3 | ASR 依赖腾讯云（闭源服务） | 转写质量与中文场景成熟度高；失败时保留录音可人工填写，不阻塞主线 | `ASR_PROVIDER` 已预留扩展位：增加可插拔实现（本地 faster-whisper / 讯飞等），本地模型可让录音数据不出机器 |
| 4 | 仅微信小程序一端 | 长辈零安装、家庭群传播链，是讲述者到达率的最优解 | 核心 API 端无关：以 Taro 跨端重构产出 **H5 版**（评委浏览器直达、无微信限制），App（后台长录音、离线）在有真实需求证据后评估；原生双端重写不在计划内 |
| 5 | 单家庭共享数据库 | 演示账号同属一个家庭，降低理解成本 | 完成家庭邀请接受/拒绝流；数据层加家庭维度隔离与行级权限 |
| 6 | 演示账号 + 统一密码 + 固定验证码 | 保证现场演示可复现，未接入真实短信 | 正式注册流程（真实短信验证码）、密码策略、`ALLOW_AUTO_REGISTER` 灰度开关 |
| 7 | LLM 走 OpenAI 兼容云服务 | 通义 / 智谱 / DeepSeek 等即插即用 | 预留本地模型（Ollama / vLLM）接入，实现全离线运行 |
| 8 | 动态插画、回忆录编辑 Agent、美术编排 Agent | 设计已就绪（见架构图解），实现排期靠后 | 按纪念册 → 编辑 Agent → 美术 Agent 顺序推进 |
| 9 | 审计规则层对汉字数字篡改、长句掩护实体替换存在漏报（拦截率 88%，见评测报告） | anchor 正则目前只识别阿拉伯数字年份/年龄；重合度阈值以字符公共子串为准 | anchor 扩展汉字数字；审计 Prompt 增加"数值与实体一致性专项核对"；审计层暂不用推理型模型（实测 JSON Schema 失败率 100%，见评测报告 llm 篇） |

## 合规与可信基础

- 每条 AI 参与生成的内容都带来源说明与证据链，发布必须经人工确认——这与《深度合成管理规定》对 AI 生成内容的标识要求方向一致。
- 录音、转写与故事数据存放在运行后端的本机数据库，不进入第三方存储；仅在启用 ASR / 真实模型时，相应音频或文本发送至对应厂商（见 README 数据边界说明）。
- 项目的长期方向是给"可信"建立可测量的证据：审计拦截率、误报率等评测能力在规划中。

## 已实现 vs 规划中速览

- **已实现**：录音转写与三份文本分离、七要素证据链、LangGraph 采访（暂停/恢复）、双风格写作与逐句证据、事实审计门、家庭纪念册与 PDF 导出、98 项自动化测试。
- **进行中 / 规划**：家庭邀请流程、真实短信、公网部署、多进程任务队列、可插拔 ASR、H5 端、RAG 记忆检索、动态插画与编辑类 Agent。
